> Document rédigé en français, comme la [revue d'architecture](REVUE-ARCHITECTURE.md), à la demande du commanditaire (le reste du dépôt est en anglais, voir `CONTRIBUTING.md`). Analyse du 14/11/2026 sur le commit `c82cd5c` (`main` à cette date), faite par lecture du code. **Le backlog vit dans les issues** : l'épopée [#141](https://github.com/yp44/powerj/issues/141) et ses 46 sous-issues `[AUDITv2] …` ; l'état d'un constat est celui de son ticket, ce document n'est pas mis à jour.

## Contexte

PowerJ (shell objet « esprit PowerShell » en Java 25 ; 10 modules Maven/JPMS ; ≈ 30 700 lignes de production, ≈ 32 600 de tests, ≈ 2 100 tests ; 208 commits en quatre semaines) a déjà eu deux revues : `docs/REVUE-ARCHITECTURE.md` (24/10, phases 0 à 5 réalisées) et l'audit de code du 30/10 piloté par l'issue #77 (22 sous-issues sur 29 fermées). Cet **audit v2** porte sur `main` au 14/11/2026 (`c82cd5c`) et sur cinq axes : robustesse, clarté, bonnes pratiques, stabilité, expérience utilisateur du shell. Il ne répète pas ce que les 23 issues ouvertes suivent déjà (#47 à #138) ; il les cite quand un constat les renforce.

Livrables : ce rapport (analyse, points critiques, phases), **les 46 tickets GitHub** (45 créés le 14/11, plus [#190](https://github.com/yp44/powerj/issues/190) ajouté le 15/11 en phase 0) préfixés `[AUDITv2]` et rédigés en anglais (convention du dépôt), et l'issue-épopée [#141](https://github.com/yp44/powerj/issues/141) qui les relie sur le modèle de #77 (décisions prises avec le commanditaire en fin de document).

## 1. Ce qui est bien fait (à préserver)

1. **L'architecture tient ses promesses et des tests les gardent** : couches du cœur, `cmdlets ⇏ core`, `shell` qui ne lit le processus qu'en trois classes, un seul point d'arrêt de la JVM — 14 règles ArchUnit, une seule ligne gelée (`Language.current`).
2. **Le shell est une vraie racine de composition** : `ShellBootstrap` lit la ligne de commande, `Environment` isole le processus, `Main` fait 16 lignes ; un shell complet démarre dans un test sur un `TestTerminal` (JLine réel en mémoire : `ReplLoopTest`, `ShellBootstrapTest`).
3. **Un superviseur pour chaque ligne** : `Supervisor` attrape tout `Throwable` sur un fil de 16 Mo, `switch` exhaustif (OOM avec réserve mémoire, StackOverflow, LinkageError), second Ctrl+C = abandon ; `IOError` du terminal → code 1 ; gestionnaire Ctrl+C remis ; `System.out` redirigé vers JLine ; hook d'arrêt qui restaure le terminal ; le journal ne garde jamais une ligne tapée (`LoggedLine`).
4. **Un seul endroit appelle Java** : `JavaInvoker.call` consulte `CallPolicy` et `PreviewGuard` avant chaque méthode, `Method.invoke` compris ; caches de réflexion en `ClassValue` (pas de fuite de classe) ; imports remplacés par instantané immuable.
5. **L'aperçu et le perf sont des modes d'un `ModeController`**, « le dernier gagne » est une classe testée (`LatestWinsRunner`), les réglages se changent au clavier sous la bannière : une UX d'outil interactif.
6. **Opérations destructives prudentes** : `ProtectedPaths` relu à chaque commande (défauts si le fichier manque), `RealPaths` résout les liens des parents, `mv` sans `-f` n'écrase pas, copie inter-volumes qui ne supprime la source qu'après succès, `--dry-run` partout ; consentement natif lié au SHA-256 de tout ce qui est chargé.
7. **Annulation soignée côté pipeline** : `Pipe` bornée, abandon en cascade idempotent, `joinAll` avec échéance qui rend le drapeau, états de cmdlet fermés quelle que soit la fin (`CmdletRunner`), `Properties.Unreadable` et `ScriptBlock.tryInvoke` impossibles à confondre avec Ctrl+C, regex interruptibles (`GuardedText`).
8. **Processus natifs** : environnement de la session et jamais celui de la JVM, arguments en liste (pas de shell), repli `sh` par `"$0" "$@"`, `destroyTree` avec délai de grâce, `PosixJobs` qui ne tue qu'un pid encore à lui, handles Windows restreints (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`), `.bat` refusés (CVE-2024-24576).
9. **Moteur de parcours sain** (`FileWalker`/`FileTrees`) : file bornée, consommateurs dans le fil appelant, `shutdownNow()` en `finally`, erreurs en valeurs, `DirectoryIteratorException` traitée (#83).
10. **JSON/CSV maison mais contrôlés** : 316 fichiers de JSONTestSuite, RFC 4180, profondeur 1 000, valeur > 64 Mi arrêtée, substituts isolés échappés ; `ValueUnroller` ferme toujours les flux.
11. **i18n propre** : parité des clés en/fr vérifiée par test, 0 `toLowerCase` sans `Locale` dans les cmdlets, 0 texte anglais en dur côté cmdlets, « did you mean » des options qui ne devine jamais entre plusieurs noms.
12. **`powerj-fx` bien découpé** : `model` sans contrôles JavaFX, ports, toolkit démarré une fois avec échec mémorisé et délai, `LiveTable` bornée, `RowShape` partagée, noms accessibles sur chaque champ.
13. **Chaîne de qualité au-dessus de la moyenne** : JaCoCo 80 % par module, Spotless, Enforcer, `-Xlint:all` compté en CI, Error Prone et PIT opt-in, snapshot de l'API, traçabilité FR-nn par test, `InterpreterCharacterizationTest` (≈ 70 lignes figées), CI Linux/macOS/Windows avec fumée sur l'image empaquetée, actions épinglées par SHA, Dependabot.
14. **Documentation hors norme** : spécification « document vivant », 12 ADR, 32 fiches de recette, CHANGELOG détaillé, CONTRIBUTING (langue, « test rouge d'abord »).

## 3. Points critiques à corriger en premier

1. **R-01 — Ctrl+C perdu sur un appel Java interrompu** : la promesse centrale du README (« Ctrl+C cancels the running command ») est fausse dès qu'un `Thread.sleep` ou un appel réseau est dans la ligne, et un `; rm` qui suit s'exécute. Deux `catch` et un test.
2. **S-01 — la CI de `main` a échoué sur un test non déterministe** : chaque relance coûte un cycle et habitue à ignorer le rouge.
3. **B-02/B-03 — les montées de version sont bloquées par deux assertions sur le nom de module des cmdlets de test** ; plus on attend, plus le saut (JavaFX 27, actions v7, Maven 3.10) est risqué.
4. **U-01/C-01 — un utilisateur peut rester coincé à l'invite `>>` sur du Java légal** : la seule situation trouvée où le shell ne « répond » plus.
5. **R-08, R-09, R-10 — trois défauts des commandes destructives ou de copie** : `mv -f x lien` remplace le lien, `rm "x?.txt"` supprime plus que demandé, `cp -r` échoue sur un arbre en lecture seule.
6. **S-04/S-05 — `cat` peut faire mourir la session (OOM) et `grep` garde un fichier entier en mémoire** : contredit « the shell never crashes » sur de gros fichiers.
7. **R-02 — un record de paramètres avec `float` casse le cmdlet d'un auteur tiers à chaque appel**, et rien ne le lui dit à l'enregistrement : le défaut de SPI le plus cher à découvrir tard.
8. **B-01 — le consentement natif n'est pas la barrière que sa Javadoc décrit** : une ligne dans le lanceur (`--illegal-native-access=deny`) ou une Javadoc honnête, à décider.
9. **U-07 — `ps \| kill` sans garde-fou** alors que `rm` en a.
