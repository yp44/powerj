# Acceptance test — Mini-iteration 9: internationalization (en / fr)

**Goal:** verify that PowerJ prints its messages in English or French, that the language is chosen with `POWERJ_LANG` or the `language` key of `config.properties` (in this order of precedence, the system language being the default), and that every kind of message follows: errors, `which`, help, completion, `mod-list`, a third-party module, number formatting.

> Messages are shown in the system language; set `language=en` in config.properties (or `POWERJ_LANG=en`) to get the English texts quoted here. This recipe sets the language explicitly in each scenario.

## Getting the deliverables

As in the previous steps: **Actions** tab, latest run of the **CI** workflow, artifact `powerj-windows-x64-installer` or `powerj-windows-x64-portable`; for scenarios 14 and 15, also the **`greet-module`** artifact (`greet.jar`, to copy into `%USERPROFILE%\.powerj\modules\`, see acceptance test 7).

Before starting: make sure that `POWERJ_LANG` is not set (`echo %POWERJ_LANG%` in `cmd.exe` displays `%POWERJ_LANG%`) and that `%USERPROFILE%\.powerj\config.properties` contains no `language` line.

## How the language is chosen

The language is resolved **once, at startup**; the first source that gives a value wins:

| Priority | Source | Example |
|---|---|---|
| 1 | Java system property `powerj.language` | `-Dpowerj.language=fr` (tests, embedding) |
| 2 | Environment variable `POWERJ_LANG` | `set POWERJ_LANG=en` in `cmd.exe`, then `powerj` |
| 3 | Key `language` of `config.properties` | `language=fr` in `%USERPROFILE%\.powerj\config.properties` (or `%POWERJ_HOME%\config.properties`) |
| 4 | Display language of the system | French Windows → French; any other language → English |

Only `en` and `fr` exist: a value starting with `fr` (`fr`, `fr_FR`) gives French, anything else gives English.

## Scenario

For the scenarios run in both languages, open `cmd.exe`, type `set POWERJ_LANG=en` (or `fr`) and launch PowerJ **from this window** (`powerj`, or the full path of `powerj.exe` for the portable version); `exit` and change the variable to switch.

## What stays the same in both languages

- The **input syntax**: commands, cmdlets and options (`ls --recurse`, `where`, `help members`), keywords (`true`, `null`, `now`, `new`, `import`), units (`10kb`, `7d`), values of options (`--on-error stop|continue|silent`).
- Java names (`FileEntry`, `name`, `size`), the messages of Java exceptions (`For input string: "x"`, produced by the JDK) and the output of native programs (`git`, `ipconfig`).
- The diagnostic log `%USERPROFILE%\.powerj\logs\powerj.log`, always in English.

## Known limitations

- Only English and French: no other language, and no per-session change (`env --set POWERJ_LANG` has no effect until the next start).
- A third-party module that does not implement `CmdletProvider.messages(Locale)` shows its annotation texts (English by convention) whatever the language; its own messages are in the language its author wrote them in.
- Dates keep their fixed format (`2026-10-07 10:12`) in both languages; only the decimal separator of sizes follows the language.
- Older acceptance tests (steps 0 to 8) quote the English texts: run them with `POWERJ_LANG=en` or `language=en`.
